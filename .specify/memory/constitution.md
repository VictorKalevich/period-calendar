# Календарь цикла Constitution

## Core Principles

### I. Приватность

- Все данные цикла (даты, отметки, заметки, настройки) MUST храниться только на устройстве
  пользователя в IndexedDB.
- На сервер MAY передаваться только push-подписка и даты/тексты запланированных напоминаний.
  Тексты напоминаний MUST NOT раскрывать данные цикла сверх необходимого для уведомления.
- В приложении MUST NOT быть аккаунтов, регистрации, аналитики, трекеров, телеметрии и
  сторонних скриптов, отправляющих данные на внешние серверы.
- Любой новый сетевой запрос MUST быть явно обоснован в плане фичи со ссылкой на этот принцип.

**Обоснование**: данные о менструальном цикле — чувствительная медицинская информация;
лучшая защита — не собирать её вовсе.

### II. Офлайн-PWA без платной инфраструктуры

- Приложение — PWA для iPhone (Safari, установка на экран «Домой»). Нативная сборка
  (Xcode, App Store, обёртки вроде Capacitor) MUST NOT использоваться.
- Все функции, кроме доставки push-уведомлений, MUST работать полностью офлайн после первой
  загрузки (Service Worker кэширует все ресурсы приложения).
- Хостинг — GitHub Pages; push-бэкенд — бесплатный тариф Cloudflare Worker.
  Платные сервисы и подписки MUST NOT использоваться.
- Возможности платформы MUST проверяться на совместимость с iOS Safari (в т.ч. Web Push для
  установленных PWA, iOS 16.4+).

**Обоснование**: приложение для личного использования без затрат и без зависимости от сети.

### III. Сохранность данных

- Обновление приложения MUST NOT приводить к потере или порче пользовательских данных.
- Схема хранения MUST иметь номер версии; каждое изменение схемы MUST сопровождаться
  миграцией с предыдущей версии, покрытой тестом.
- Миграции MUST быть идемпотентными и не удалять данные, которые они не умеют преобразовать.
- Приложение MUST предоставлять экспорт всех данных в JSON-файл и импорт из него;
  файл резервной копии MUST содержать версию схемы, а импорт старых версий MUST проходить
  через те же миграции.

**Обоснование**: данные существуют только на устройстве, резервной копии на сервере нет.

### IV. Корректность прогноза (TDD, NON-NEGOTIABLE)

- Вся логика прогноза (следующая менструация, фертильное окно, овуляция, длины циклов) MUST
  находиться в отдельном доменном модуле из чистых функций без доступа к DOM, хранилищу,
  сети и текущему времени (текущая дата передаётся параметром).
- Доменный модуль MUST разрабатываться тестами вперёд: тест пишется и падает до реализации
  (Red-Green-Refactor).
- Тесты MUST покрывать пограничные случаи как минимум: отсутствие истории, одна запись,
  нерегулярный цикл, выбросы, переход через месяц и год, високосный год, смену часового
  пояса/летнего времени.
- Даты в доменном модуле MUST обрабатываться как календарные дни (без времени суток),
  чтобы исключить ошибки смещения.

**Обоснование**: ошибка прогноза напрямую вводит пользователя в заблуждение; чистые функции
легко и надёжно тестируются.

### V. Простота

- Зависимости MUST быть минимальными; каждая новая runtime-зависимость MUST быть обоснована
  в плане (почему нельзя обойтись платформой браузера или несколькими строками кода).
- Коммиты MUST быть маленькими и атомарными; каждый коммит MUST собираться и проходить тесты.
- Предпочтение — простейшее решение, удовлетворяющее требованиям (YAGNI).

**Обоснование**: небольшое приложение должно оставаться понятным и легко поддерживаемым.

### VI. Дизайн и доступность

- Интерфейс MUST соответствовать согласованным макетам; отклонения MUST быть согласованы
  до реализации.
- Светлая и тёмная темы MUST переключаться автоматически по системной настройке iPhone
  (`prefers-color-scheme`).
- Контраст текста MUST быть не ниже 4.5:1 (WCAG AA) в обеих темах; зоны нажатия MUST быть
  не меньше 44×44 px.
- Язык интерфейса — русский; все пользовательские тексты, даты и форматы MUST быть
  локализованы под русский язык (`ru-RU`, неделя с понедельника).

**Обоснование**: приложением пользуются ежедневно на iPhone; удобство и читаемость важнее
декоративности.

### VII. Честность

- Приложение MUST явно сообщать, что прогноз ориентировочный и не заменяет контрацепцию
  и консультацию врача; пометка MUST быть доступна в интерфейсе постоянно (не только при
  первом запуске).
- Прогнозы при недостатке данных или нерегулярном цикле MUST отображаться с пониженной
  уверенностью или явной оговоркой, а не как точные даты.

**Обоснование**: ложная уверенность в прогнозе может иметь серьёзные последствия для
пользователя.

## Технические ограничения

- Платформа выполнения: iOS Safari (установленная PWA) — основная цель; остальные браузеры
  поддерживаются по возможности.
- Хранилище: IndexedDB с версионированной схемой; `localStorage` допускается только для
  несущественных настроек интерфейса.
- Сеть: единственный внешний сервис — Cloudflare Worker для push-уведомлений; хостинг
  статики — GitHub Pages.
- Секреты (например, VAPID private key) MUST храниться только в настройках Cloudflare Worker
  и MUST NOT попадать в репозиторий.

## Процесс разработки и контроль качества

- Каждая фича проходит цикл Spec Kit: спецификация → план (с разделом Constitution Check) →
  задачи → реализация.
- Перед слиянием MUST проходить все тесты; изменения доменного модуля без тестов MUST NOT
  приниматься.
- Изменения схемы хранения MUST включать миграцию и тест миграции с предыдущей версии.
- Изменения UI MUST проверяться в обеих темах и на соответствие требованиям контраста и
  размера зон нажатия.

## Governance

- Конституция имеет приоритет над остальными практиками и документами проекта.
- Поправки вносятся изменением этого файла с описанием причины; затрагивающие планы и
  задачи MUST быть пересмотрены на соответствие.
- Версионирование — семантическое: MAJOR — удаление или переопределение принципа;
  MINOR — новый принцип или раздел, существенное расширение; PATCH — уточнения формулировок.
- Каждый план фичи MUST содержать проверку соответствия конституции; любое отступление MUST
  быть явно обосновано в разделе Complexity Tracking.
