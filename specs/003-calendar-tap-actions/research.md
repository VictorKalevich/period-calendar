# Research: Нажатие на дату и умные действия «Месячные»

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

## R1. Подавление выделения, лупы и подсветки на iOS

- **Decision**: на сетке месяца, пейджере и полоске недели — CSS `user-select: none`,
  `-webkit-user-select: none`, `-webkit-touch-callout: none`, `-webkit-tap-highlight-color:
  transparent`; на ячейках дополнительно `onContextMenu → preventDefault()`; `touch-action:
  manipulation` (уже у кнопок) убирает задержку двойного тапа.
- **Rationale**: в iOS Safari лупа и меню «Скопировать» появляются из-за выделяемого текста и
  callout'а; эти свойства — штатный способ их отключить без JS-обработки касаний и без поломки
  прокрутки scroll-snap.
- **Alternatives**: `preventDefault` на `touchstart` — ломает свайп пейджера; заменить числа на
  SVG/canvas — избыточно.

## R2. Где вычислять состав диалога

- **Decision**: чистая функция `periodActionsFor(date, today, periods, periodLength)` в
  `src/domain/periods.ts` возвращает массив действий `{ kind, label, apply(): Result<Period[]> }`;
  UI только отрисовывает кнопки и сохраняет результат `apply()`.
- **Rationale**: FR-006 требует правил, независимых от интерфейса, и тестов на каждую строку
  таблицы; Конституция IV — логика в домене, тесты вперёд.
- **Alternatives**: условия в компоненте `PeriodSheet` — нетестируемо без DOM.

## R3. «Конец не меняется» при переносе начала незакрытых месячных

- **Decision**: общая функция `setPeriodStart`: если у месячных `end = null`, а прежний оценочный
  последний день (`прежнее начало + L − 1`) не позже сегодняшнего, он сохраняется как
  `end` с `endEstimated = true`; если позже — `end` остаётся `null` (месячные ещё идут).
- **Rationale**: инвариант data-model «end ≤ сегодня» сохраняется; оценочные концы не входят в
  среднюю длину (FR-014 фичи 001).
- **Alternatives**: хранить будущий конец — ломает отображение прогнозной части и инвариант.

## R5. Слияние месячных (ревизия 2)

- **Decision**: чистая `normalizePeriods(periods, today, L)` в домене вызывается внутри всех
  изменяющих функций (`markPeriodStart`, `markPeriodEnd`, `setPeriodStart`, `apply` действий),
  в `parseBackup` (импорт) и один раз при запуске (`normalizeStoredPeriods` в репозитории —
  перечитывает отметки и сохраняет, только если что-то изменилось). Схема БД не меняется,
  поэтому миграция версии не нужна.
- **Rationale**: единая точка правил слияния, тестируемая без БД; данные старых версий
  приводятся к инварианту без изменения `SCHEMA_VERSION`.
- **Alternatives**: миграция Dexie v2 — избыточна, схема та же; слияние только при отображении —
  данные остались бы «двумя месячными», статистика и прогноз считали бы их отдельно.
- **Идущие месячные (ревизия 3)**: при слиянии с ещё идущими конец объединённых — их оценка
  (`max(начало + L − 1, сегодня)`), `endEstimated = true`, может быть в будущем. Инвариант 001
  уточнён: в будущем не может быть только отмеченный вручную конец; дни после сегодняшнего у
  оценочного конца рисуются как прогноз (`dayInfo`).
- **Лимит 15 дней**: слияние, дающее > 15 дней, не выполняется; действия с таким итогом недоступны.

## R4. Открытие диалога по нажатию

- **Decision**: `CalendarScreen` при выборе дня `≤ today` открывает `PeriodSheet`; для `> today`
  только выбирает. На «Сегодня» плитки сегодняшнего и прошедших дней — кнопки, будущие — `<li>`
  без кнопки (`aria-disabled` не нужен: элемент не интерактивный).
- **Rationale**: SC-001 — 2 нажатия; будущие дни нельзя отметить (FR-009 фичи 001).
