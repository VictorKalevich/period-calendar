# Data Model: фича 007

## Settings (kv `settings`) — схема v5

| Поле | Тип | По умолчанию | Источник |
|------|-----|--------------|----------|
| `remindMissedPeriod` | boolean | `true` | FR-001, FR-010 |

Прочие поля без изменений (001 data-model, 004–006).

**Миграция v4 → v5** (`migrations[4]`): `settings.remindMissedPeriod ??= true`; прочие поля и таблицы не
трогаются; повторное применение ничего не меняет. Применяется в `db.version(5).upgrade` и при импорте
копий `schemaVersion` 1–4.

**Валидация копии**: `remindMissedPeriod` — boolean, иначе «некорректные настройки напоминаний».

## Reminder (домен, не хранится)

| Поле | Значение для нового вида |
|------|--------------------------|
| `kind` | `'missedPeriod'` (на сервер не уходит) |
| `id` | `missed-period:YYYY-MM-DD` (дата отправки) |
| `sendAt` | 12:00 местного времени в день «исходное прогнозное начало + 2» |
| `title` | `Календарь цикла` |
| `body` | `Похоже, месячные уже начались — не забудь отметить их в календаре` |

Заголовок `ovulation` меняется: `Овуляция` → `Календарь цикла`; тела `period` и `ovulation` без изменений.

На сервер (PUT расписания) по-прежнему уходят только `{ id, sendAt, title, body }`.
