# Data Model: Отметка секса, несколько настроений и интенсивность самочувствия

Изменения относительно [001 data-model](../001-cycle-calendar/data-model.md). Схема хранения v5 → **v6**,
резервная копия `schemaVersion: 6`. Таблицы и индексы Dexie не меняются (`periods: 'id, start'`,
`days: 'date'`, `kv: 'key'`).

## DayEntry — запись дня (v6)

| Поле | Тип | Правило |
|------|-----|---------|
| `date` | LocalDate | ключ |
| `symptoms` | SymptomId[] | известные коды, без повторов, порядок справочника (как было) |
| `intensity` | `Partial<Record<SymptomId, Intensity>>` | **новое**; только для кодов из `symptoms`; `{}` по умолчанию |
| `moods` | MoodId[] | **новое**, заменяет `mood`; известные коды, без повторов, порядок справочника |
| `sex` | boolean | **новое**; `false` по умолчанию |
| `note` | string | trim, ≤ 1000 (длиннее — обрезается при мягком разборе) |

`Intensity = 'mild' | 'moderate' | 'severe'` — подписи «слабо», «средне», «сильно».
Поле `mood` (v1–v5) удаляется переносом. Мягкий разбор любых входных данных —
[contracts/day-entry.md](./contracts/day-entry.md).

Запись пуста ⇔ нет `symptoms`, `moods`, `sex` и `note`; пустая не хранится.

## Settings (v6)

| Поле | Тип | Свежая установка | Перенос с v1–v5 (`migrations[5]`) | Смысл |
|------|-----|------------------|-----------------------------------|-------|
| `showMood` | boolean | `false` | = `showWellbeing` | «Настроение» видно |
| `showIntensity` | boolean | `false` | `false` | «Интенсивность самочувствия» видна |
| `showSex` | boolean | `false` | `false` | «Отметка секса» видна |

`showWellbeing` теперь — только самочувствие (физические отметки). Перенос идемпотентен (`??`).

## Перенос v5 → v6

- `db.version(6).upgrade`: (1) настройки — `migrations[5]`; (2) `days` — каждая запись заменяется на
  `coerceDayEntry(запись)`; если результат `null` — запись не трогается; ошибка одной записи и ошибка
  прохода по таблице перехватываются и не мешают открытию базы. `periods` и `PushState` не трогаются.
- `migrations[5]` (импорт копий v1–v5): настройки — как выше; `data.days`, если массив, — каждый элемент
  через `coerceDayEntry`, `null` остаются как есть (их отбросит разбор импорта).

## Производные (домен)

- `DayContext.sexDates: ReadonlySet<LocalDate>` — дни с отметкой секса (пусто при `!showSex`).
- `DayInfo.sex: boolean`.
- `DayDialog.sex: 'mark' | 'unmark' | null`; `DayExtra = 'wellbeing' | 'mood' | 'notes'`.
