# Research: Отметка секса, несколько настроений и интенсивность самочувствия

Неизвестных в Technical Context нет; ниже — проектные решения.

## R1. Новая форма записи дня

**Decision**: `DayEntry` v6 = `{ date, symptoms: SymptomId[], intensity: Partial<Record<SymptomId,
Intensity>>, moods: MoodId[], sex: boolean, note }`. Поле `mood` удаляется; `Intensity = 'mild' |
'moderate' | 'severe'`. Все новые поля обязательны в хранимой записи (пустые значения — `{}`, `[]`,
`false`), чтобы UI не проверял `undefined`.

**Rationale**: набор настроений — массив кодов, как у самочувствия; степень — словарь по коду
самочувствия, поэтому снятие пункта легко удаляет его степень, а выключение интенсивности ничего не
трогает. Отметка секса — булево значение (решение «просто факт», количество не важно).

**Alternatives considered**: `symptoms: { id, intensity }[]` — ломает простую форму `symptoms` и все
места, где она используется (сводка, точки, будущий отчёт); `sex: number` (количество) — отклонено в
переписке; хранить и `mood`, и `moods` для отката — две правды о настроении, путаница.

## R2. Мягкий разбор записи дня («ошибки ловим, части становятся пустыми»)

**Decision**: одна чистая функция `coerceDayEntry(raw: unknown, legacy?)` в `src/domain/dayEntry.ts`
приводит **любое** значение к корректной записи: `null` — только если нет корректной даты. Правила по
полям — [contracts/day-entry.md](./contracts/day-entry.md). Длинная заметка обрезается до 1000 символов
(текст пользовательницы важнее строгости). Используется везде, где запись приходит «снаружи»: перенос
базы v5 → v6, чтение из базы (`getDayEntry`, `getDayEntries`, `useForecast`), импорт копии, сохранение.
Строгий `normalizeDayEntry` заменяется на `coerceDayEntry`.

**Rationale**: требование владельца — приложение не падает, история циклов не теряется. Если запись дня
читается мягко на всех входах, ни одна испорченная запись (в том числе записанная старой сборкой при
откате) не может сломать экран или импорт.

**Alternatives considered**: строгая проверка с отказом импорта (как было) — отклонено владельцем;
мягкость только в миграции — запись старой формы, попавшая в базу при откате, ломала бы чтение.

## R3. Перенос базы v5 → v6 без риска «база не открывается»

**Decision**: `db.version(6).upgrade` меняет записи `days` через `toCollection().modify()`, каждая
запись — в `try/catch`; если `coerceDayEntry` вернул `null` (нет даты) — запись не трогается. Вся
работа с записями дней в `upgrade` обёрнута в `try/catch`: ошибка не прерывает открытие базы, а
неперенесённые записи всё равно читаются мягко (R2). Настройки — `migrations[5]` (как в v2–v5).

**Rationale**: исключение в `upgrade` Dexie откатывает версию и база не открывается — это и есть
«приложение упало и не показывает циклы». Месячные в `upgrade` не участвуют вовсе.

**Alternatives considered**: переносить записи только при чтении, без `upgrade` — в базе навсегда
остаются две формы записей и резервная копия выгружала бы старую форму.

## R4. Таблица кодов настроений

**Decision**: 20 кодов (порядок показа = порядок справочника): `joyful` Радостная, `cheerful` Весёлая,
`content` Довольная, `delighted` В восторге, `inspired` Воодушевлённая, `energetic` Энергичная,
`playful` Игривая, `calm` Спокойная, `tender` Нежная, `confident` Уверенная, `grateful` Благодарная,
`sensitive` Чувствительная, `sad` Грустная, `anxious` Тревожная, `irritable` Раздражённая, `angry`
Злая, `lonely` Одинокая, `overwhelmed` Перегруженная, `indifferent` Безразличная, `mood_swings`
Настроение меняется. Старые коды `calm`, `sensitive`, `sad`, `anxious`, `irritable` сохраняются (меняются
только подписи); `LEGACY_MOOD_CODES = { great: 'joyful' }`. Неизвестные коды отбрасываются.

**Rationale**: сопоставление «по кодам» — подписи можно переформулировать без миграций; для пяти из
шести старых значений перевод не нужен вовсе.

**Alternatives considered**: новые коды для всех — потребовало бы шести правил перевода вместо одного.

## R5. Переключатели и значения по умолчанию

**Decision**: `Settings.showMood`, `showIntensity`, `showSex` (по умолчанию `false`). `migrations[5]`:
`showMood ??= showWellbeing`, `showIntensity ??= false`, `showSex ??= false` — идемпотентно. «Самочувствие»
(`showWellbeing`) теперь только физические отметки.

**Rationale**: свежая установка — всё новое выключено (требование владельца). У обновившихся настроение
было частью «Самочувствия»; если оно было видно — остаётся видно (иначе «пропали записи»).

## R6. Импорт резервной копии: что строго, что мягко

**Decision**: `parseBackup(text, current: Settings)`:
- весь разбор — в `try/catch` → «Файл резервной копии повреждён: …», данные не меняются;
- месячные — строго, как раньше (история циклов — главное; частичная история хуже, чем текущая);
- записи дней — `coerceDayEntry`; без даты — пропуск, повтор даты — первая;
- настройки — каждое поле проверяется отдельно, некорректное → значение `current` («старая база имеет
  приоритет»); отсутствие объекта настроек → `current` целиком.
`BackupSection` передаёт текущие настройки и оборачивает чтение файла в `try/catch`.

**Rationale**: в копии самое ценное — месячные; отметки дня и настройки не повод отказываться от
восстановления истории.

**Alternatives considered**: импортировать корректные месячные, пропуская испорченные — частичная
история молча заменит полную на устройстве; отказ импорта при испорченной настройке — отклонено.

## R7. Сердечко в календаре и в легенде

**Decision**: `DayContext.sexDates` (пусто при выключенном переключателе) → `DayInfo.sex`. Значок
`Heart` 14×14 в левом верхнем углу кружка (top −6, left −5), заливка `btnBg`, обводка 2 px `surface`
(отделяет значок от заливки месячных и фертильного окна). Контраст `btnBg` к `surface` — 4.53:1 /
≥ 3:1 в тёмной теме (графический объект, WCAG 1.4.11). Пункт легенды «Секс» с тем же значком — только
при включённом переключателе.

**Alternatives considered**: значок под числом вместо точки — конфликтует с точкой «Есть записи»;
эмодзи — запрещены design.md.

## R8. Диалог дня и листы

**Decision**: `dayDialogFor(..., entry)` возвращает `sex: 'mark' | 'unmark' | null` (null — переключатель
выключен или будущий день) и `extras: ('wellbeing' | 'mood' | 'notes')[]`. Кнопка отметки — сразу после
кнопок месячных, обычная пилюля с иконкой сердечка; переключение сохраняется сразу, лист закрывается.
Выбор настроения — новый лист `MoodPicker` («Настроение · 24 октября», чипы, «Готово»). `SymptomPicker`
показывает только самочувствие и, при `showIntensity`, под чипами строку на каждый отмеченный пункт:
подпись + три сегмента «слабо / средне / сильно» (`aria-pressed`, высота 44).
Все листы сохраняют запись как `{ ...entry, <своё поле> }` — чужие поля не теряются.

## R9. Зависимости и производительность

**Decision**: без новых зависимостей. Перенос — один проход по `days` (сотни записей), мгновенно.
