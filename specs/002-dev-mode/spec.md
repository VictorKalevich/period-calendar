# Feature Specification: Скрытый режим разработчика

**Feature Branch**: `002-dev-mode`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "Скрытый режим разработчика: внизу Настроек строка «Версия X.Y.Z», 7 нажатий подряд включают режим (сообщение «Режим разработчика включён»), повторные 7 — выключают; флаг хранится локально. В режиме разработчика раздел «Для разработчика» с кнопкой «Проверить уведомление»: воркер сразу отправляет на это устройство push «Календарь цикла» / «Уведомления работают». На воркере тестовая отправка — только на подписку того же клиента (по его токену) и не чаще 1 раза в минуту."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Включить и выключить режим разработчика (Priority: P1)

Внизу экрана «Настройки» видна строка «Версия X.Y.Z». Семь нажатий подряд включают режим
разработчика, ещё семь — выключают. Обычная пользовательница режим случайно не найдёт.

**Why this priority**: без режима раздел «Для разработчика» недоступен.

**Independent Test**: нажать на строку версии 7 раз — появляется «Режим разработчика включён» и
раздел «Для разработчика»; перезапустить приложение — режим остался; нажать ещё 7 раз — «Режим
разработчика выключен», раздел исчез.

**Acceptance Scenarios**:

1. **Given** режим выключен, **When** 7 нажатий на строку версии с паузами не больше 1 с,
   **Then** показано сообщение «Режим разработчика включён» и появляется раздел «Для разработчика».
2. **Given** режим включён, **When** ещё 7 таких нажатий, **Then** «Режим разработчика выключен»,
   раздел скрыт.
3. **Given** сделано 4 нажатия, **When** пауза больше 1 с и ещё 3 нажатия, **Then** режим не
   переключается (счёт начинается заново).
4. **Given** режим включён, **When** приложение закрыто и открыто снова, **Then** режим включён.

---

### User Story 2 - Проверить доставку уведомлений (Priority: P1)

В разделе «Для разработчика» кнопка «Проверить уведомление» просит сервер сразу отправить на это
устройство push «Календарь цикла» / «Уведомления работают».

**Why this priority**: позволяет проверить цепочку push без ожидания 12:00 (задача T072).

**Independent Test**: включить напоминания, включить режим разработчика, нажать «Проверить
уведомление» — через несколько секунд приходит уведомление; повторное нажатие в течение минуты
сообщает об ограничении.

**Acceptance Scenarios**:

1. **Given** напоминания включены, **When** нажата «Проверить уведомление», **Then** в течение
   нескольких секунд приходит уведомление с заголовком «Календарь цикла» и текстом
   «Уведомления работают», а в приложении — «Уведомление отправлено».
2. **Given** тестовое уведомление отправлено меньше минуты назад, **When** кнопка нажата снова,
   **Then** уведомление не отправляется, показано «Можно не чаще раза в минуту».
3. **Given** напоминания не включены, **When** открыт раздел, **Then** кнопка недоступна и есть
   подсказка «Сначала включите напоминания».
4. **Given** нет интернета, **When** нажата кнопка, **Then** показано «Нет связи с сервером».

### Edge Cases

- Запрос с чужим токеном или для несуществующего клиента — отказ, push не отправляется.
- Подписка устарела (push-сервис ответил 404/410) — запись клиента удаляется, приложение просит
  включить напоминания заново.
- Ограничение «раз в минуту» считается по попыткам отправки, в том числе неуспешным.
- Флаг режима разработчика не попадает в резервную копию и не уходит на сервер.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Внизу экрана «Настройки» MUST отображаться строка «Версия X.Y.Z» с версией приложения.
- **FR-002**: 7 нажатий подряд на строку версии (пауза между нажатиями ≤ 1 с) MUST переключать
  режим разработчика; при включении — сообщение «Режим разработчика включён», при выключении —
  «Режим разработчика выключен».
- **FR-003**: Флаг режима MUST храниться только на устройстве, переживать перезапуск и MUST NOT
  попадать в резервную копию.
- **FR-004**: В режиме разработчика MUST показываться раздел «Для разработчика» с кнопкой
  «Проверить уведомление»; вне режима раздел MUST быть скрыт.
- **FR-005**: Кнопка MUST просить сервер отправить push на подписку этого устройства с заголовком
  «Календарь цикла» и текстом «Уведомления работают»; тексты задаёт сервер, клиент их не передаёт.
- **FR-006**: Сервер MUST отправлять тестовый push только на подписку клиента, чей токен
  предъявлен в запросе.
- **FR-007**: Сервер MUST отклонять тестовую отправку чаще 1 раза в минуту для одного клиента.
- **FR-008**: Приложение MUST показывать результат: «Уведомление отправлено», «Можно не чаще раза
  в минуту», «Подписка не найдена — включите напоминания заново», «Нет связи с сервером».

### Key Entities

- **Флаг режима разработчика**: логическое значение на устройстве.
- **Запись клиента на сервере**: дополняется моментом последней тестовой отправки (для
  ограничения частоты).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Режим включается ровно на 7-м нажатии и не включается при меньшем числе или паузе > 1 с.
- **SC-002**: Тестовое уведомление приходит на устройство в течение 10 секунд после нажатия.
- **SC-003**: 100% повторных запросов в течение 60 с после предыдущего отклоняются сервером.
- **SC-004**: 100% запросов с неверным токеном отклоняются без отправки push.

## Assumptions

- Версия приложения берётся из `package.json` при сборке.
- Режим разработчика нужен владельцу для проверки; отдельной защиты кроме «7 нажатий» не требуется.
- Ограничение частоты хранится в той же записи KV; из-за согласованности KV «в конечном счёте»
  на разных узлах Cloudflare ограничение может сработать с небольшой задержкой — для одной
  пользовательницы это допустимо.
