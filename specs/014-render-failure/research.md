# Research: Сбой не оставляет пустой экран

Разбор пунктов «Проверить на этапе плана» из `docs/refactoring/step-1-render-failure.md` и решений,
которые уточняют «Набросок решения».

## R1. Как тестировать (окружение `node` не умеет границы ошибок)

**Decision**: dev-зависимость **happy-dom** (`^21.0.4`) и окружение по файлу — комментарий
`// @vitest-environment happy-dom` в начале новых UI-тестов. `vitest.config.ts` не меняется: остальные
тесты по-прежнему идут в `node`. Отрисовка — `createRoot` + `act` из React, база — `fake-indexeddb/auto`,
как в тестах хранилища. Чистая часть (общий приём `attempt`) тестируется в `node`.

**Rationale**:
- Критерии готовности поведенческие: «нижняя навигация работает, другие вкладки открываются», «лист не
  закрывается», «ошибка `useLiveQuery` показывает аварийный экран». Без DOM их можно проверить только
  вручную; `renderToStaticMarkup` не вызывает эффекты (нет `liveQuery`) и не поддерживает границы ошибок.
- Пробный тест (удалён после проверки) подтвердил: в happy-dom работают граница ошибок React 19,
  `HTMLDialogElement.showModal()` (`BottomSheet`), `fake-indexeddb`; прогон — около 0,6 с.
- Только dev: в бандл и на устройство не попадает (Конституция V касается runtime-зависимостей, но
  обоснование всё равно здесь и в plan.md). 7 транзитивных пакетов; `npm audit` новых уязвимостей не
  показал (6 прежних — цепочка `vite-plugin-pwa` → `workbox-build`).

**Alternatives considered**:
- *Только чистые части без DOM* (разметка аварийного экрана через `renderToStaticMarkup`,
  `getDerivedStateFromError`, отдельная функция состояния `useLiveQuery`) — проверяет куски, но не связку:
  ключ границы по вкладке, проброс ошибки из хука, «лист не закрылся» остаются непроверенными.
- *jsdom* — тяжелее (десятки транзитивных пакетов), `showModal()` у `<dialog>` не реализован —
  пришлось бы подменять.
- *`react-test-renderer`* — объявлен устаревшим в React 19.

## R2. Не скрывает ли граница ошибку от консоли

**Decision**: дополнительного логирования в границе не нужно; `useLiveQuery` сохраняет свою запись
`console.error('liveQuery failed', err)`; общий приём для записи и экспорта пишет
`console.error('<действие> failed', e)`.

**Rationale**: в React 19 пойманная границей ошибка передаётся `onCaughtError` корня, а его значение по
умолчанию — `console.error(error)` (`node_modules/react-dom/cjs/react-dom-client.production.js`,
`defaultOnCaughtError`). `createRoot` в `main.tsx` вызывается без опций — значит, ошибки отрисовки
по-прежнему попадают в консоль. Тест границы проверяет вызов `console.error`, чтобы будущая опция
`onCaughtError` не заглушила его незаметно.

**Alternatives considered**: `componentDidCatch` с `console.error` — дублировал бы запись React.

## R3. Один текст или разные для сбоя отрисовки и недоступной базы

**Decision**: один общий текст аварийного экрана; разница проявляется только при экспорте —
сообщением «Не удалось создать резервную копию».

**Rationale**: в обоих случаях пользовательнице нужно одно и то же — сохранить копию и перезагрузить;
надёжно различить причины на экране нельзя (сбой отрисовки тоже может вызвать испорченная запись в базе).
Экспорт читает базу заново, поэтому если она недоступна, это станет видно ровно там, где важно.

**Alternatives considered**: два текста по типу ошибки — лишняя ветка без пользы для действия.

## R4. Где стоят границы и как сбрасываются

**Decision**: класс `ErrorBoundary` (`src/ui/components/ErrorBoundary.tsx`, проп `fallback`) в двух местах:
1. в `App.tsx` вокруг `<Screen />` внутри `<main className="app__screen">` с `key={tab}` — сбрасывается при
   смене вкладки; шапка обновления и навигация вне границы и остаются рабочими;
2. в `main.tsx` вокруг `<App />` — аварийная страница `EmergencyPage` (та же карточка внутри
   `div.app > main.app__screen`, без навигации).

**Rationale**: `key={tab}` не меняет обычный путь — экран вкладки и так монтируется заново при смене
вкладки (другой тип компонента). Граница без сбоя рисует только детей, лишних DOM-узлов нет — разметка
прежняя (FR-017). Своя граница вместо `react-error-boundary` — десяток строк (Конституция V).

## R5. Как `useLiveQuery` передаёт ошибку границе

**Decision**: хук хранит `{ value } | { error }`; в обработчике `error` подписки — прежняя запись в
консоль и сохранение ошибки; при отрисовке сохранённая ошибка бросается (`throw`) — её ловит ближайшая
граница. Возвращаемый тип и обычное поведение прежние: `undefined`, пока данных нет, затем значение;
при смене `deps` прежнее значение остаётся до прихода нового.

**Rationale**: стандартный приём React — ошибки асинхронных данных попадают в границу через бросок при
отрисовке. После броска поддерево размонтируется, подписка отменяется в очистке эффекта.

## R6. Общий приём для отказа записи и экспорта

**Decision**:
- `attempt(what, action)` (`src/ui/attempt.ts`) — выполняет асинхронное действие; отказ пишет в консоль
  (`` `${what} failed` ``) и возвращает `false`, успех — `true`. Чистая функция, тест в `node`.
- `useSaveError()` и `<SaveError shown />` (`src/ui/components/SaveError.tsx`) — состояние «последняя
  запись не удалась» (`failed`, `save(write)`, `reset()`) и сообщение `notice notice--error` с
  `role="alert"` «Не удалось сохранить. Попробуйте ещё раз.»; без ошибки ничего не рисует.
- `exportData()` (`src/ui/components/share.ts`) — `attempt('export', …)` над
  `shareOrDownload(await exportBackup())`; общий для аварийного экрана и «Резервной копии».

**Rationale**: один приём вместо десяти `try/catch` (файл шага, «Набросок», п. 5). Обработчики меняются
минимально: `await saveX(); onClose()` → `if (await save(() => saveX())) onClose()`. Хук живёт в `src/ui`
— это состояние интерфейса, а не данных (`src/hooks` по правилам слоёв — домен и хранилище).

## R7. Где показывается ошибка сохранения

**Decision** (записывается в `docs/design/design.md` до кода):
- листы «Настроение», «Самочувствие» — над «Готово»; «Заметка» — над «Сохранить», в подтверждении
  удаления — над «Удалить»;
- диалог дня — на месте доменной ошибки (под кнопками месячных); в подтверждении удаления месячных — над
  «Удалить»; отказ отметки секса — там же, лист не закрывается;
- Настройки: последним элементом карточки «Цикл», «Записи дня», «Напоминания»; режим разработчика — под
  строкой версии;
- подсказка «Как получить прогноз» — отдельным блоком сразу под подсказкой (внутри подсказки
  `notice--error` слился бы с её фоном `roseSoft`);
- ошибка экспорта в «Резервной копии» — в существующем месте сообщений карточки (под кнопками).

Сообщение сбрасывается при новой попытке, при закрытии/открытии листа и при переходе между видом листа и
его подтверждением. Доменная ошибка диалога дня сбрасывается перед записью, чтобы не показывать два
сообщения сразу.

## R8. Что не входит (поведение прежнее)

- Отказ `enableReminders`, `syncReminders`, `disableReminders` (`RemindersSection`) — сбои напоминаний и
  синхронизации вне объёма (файл шага, «Границы»); общий приём охватывает только `updateSettings`.
- Фоновая `normalizeStoredPeriods` при запуске уже ловит ошибку (`main.tsx`).
- Ошибки в обработчиках, не пишущих в базу (листание, выбор дня), — нет причин для отказа.

## R9. Доступность и темы аварийного экрана

**Decision**: только существующие компоненты: `card settings-card`, заголовок `t-card-title`, текст
`t-body`, `btn btn--primary`, `btn`, `notice notice--error`.

**Rationale**: пары цветов (`ink`/`surface`, `ink`/`bg`, `btnInk`/`btnBg`, `roseText`/`roseSoft`) уже
проверяются `src/ui/theme.test.ts` в обеих темах (≥ 4.5:1); `btn` — высота `--control-h` 52 ≥ 44. Новых
классов и токенов нет — `design-system.test.ts` не затрагивается.
