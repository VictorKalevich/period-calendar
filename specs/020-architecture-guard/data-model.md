# Data Model: Правила слоёв под тестом

Данных приложения шаг не касается: схема IndexedDB, резервная копия и запросы к воркеру прежние. Ниже —
сущности теста архитектуры (`src/architecture.test.ts`); все они живут только в тестовом файле.

## Слой (`Layer`)

| Поле | Тип | Правило |
|------|-----|---------|
| `id` | строка | `domain`, `storage`, `report`, `push`, `hooks`, `pwa`, `ui`, `main`, `sw`, `env`, `worker` |
| `path` | строка | путь от корня проекта: каталог (`src/domain`) или файл (`src/main.tsx`); пути не пересекаются |
| `layers` | список `id` | слои, которые разрешено импортировать (свой — всегда) |
| `packages` | список строк | разрешённые пакеты по имени (`date-fns`, `react-dom`, `virtual:pwa-register`) |

Значения — таблица R3 в `research.md`. Каждый слой непуст: в нём есть хотя бы один исходный файл.

## Исходный файл

Файл `.ts` или `.tsx` под `src/` (на любой глубине) или `worker/src/`, имя которого не оканчивается на
`.test.ts` / `.test.tsx`. Относится ровно к одному слою — по самому длинному совпадающему `path`.
Файл без слоя — нарушение «файл вне таблицы слоёв».

## Импорт (`ImportRef`)

| Поле | Тип | Правило |
|------|-----|---------|
| `specifier` | строка или `null` | имя модуля из любой формы (R2); `null` — динамический импорт с вычисляемым именем |
| `line` | число | строка в файле, для сообщения |

## Цель импорта (`Target`)

Результат отнесения (R4):

- `{ kind: 'layer', id }` — относительный путь внутри одного из слоёв;
- `{ kind: 'package', name }` — пакет (`@scope/name`, `name`, `node:fs`, `virtual:…`);
- `{ kind: 'outside', path }` — относительный путь вне всех слоёв или абсолютный путь;
- `{ kind: 'computed' }` — вычисляемый динамический импорт; в исключениях записывается как `import(…)`.

## Исключение (`Exception`)

| Поле | Тип | Правило |
|------|-----|---------|
| `file` | строка | путь исходного файла от корня проекта |
| `target` | строка | имя пакета, `id` слоя или `import(…)` |
| `reason` | строка | непустая причина со ссылкой на фичу или решение |

Исключение разрешает ровно этот `target` ровно в этом `file`. Файл MUST импортировать `target`, иначе —
нарушение «исключение больше не нужно». Значения — таблица R5.

## Нарушение (`Violation`)

Строка `<файл>:<строка>: '<specifier>' — <правило>`, где правило — одно из:

- `слой <id> не может импортировать слой <id>`;
- `слою <id> не разрешён пакет <name>`;
- `импорт вне слоёв: <path>`;
- `динамический импорт с вычисляемым именем`;

а также без импорта: `<файл>: файл вне таблицы слоёв — отнесите его к слою` и
`<файл>: исключение <target> больше не нужно — удалите его`.

## Карта архитектуры (`docs/architecture.md`)

| Часть | Правило |
|-------|---------|
| длина | ≤ 120 строк |
| `## Слои` | таблица; первая ячейка строки — путь слоя в обратных кавычках; набор путей = набор `path` таблицы теста |
| `## Пути данных` | чтение, запись, напоминания, обновление, отчёт |
| `## Правила корректности данных` | где лежат правила настроек, записи дня, месячных, напоминаний |
| `## Чек-листы` | `### Добавить настройку`, `### Добавить отметку дня`, `### Добавить вид напоминания`; ссылка на `src/storage/migrations/README.md` |
| пути | каждый путь проекта в обратных кавычках существует (R9) |
