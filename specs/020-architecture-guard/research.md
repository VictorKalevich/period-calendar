# Research: Правила слоёв под тестом, карта архитектуры, гигиена репозитория

Шаг 7 плана рефакторинга. Разобраны пункты «Проверить на этапе плана» из
`docs/refactoring/step-7-architecture-guard.md` и вопросы, возникшие при чтении кода (ветка
`020-architecture-guard` от `refactoring`, коммит `b54eae7`). Базовая линия: приложение — 1348 тестов в 69
файлах, воркер — 111 в 4 файлах; сборка и проверка типов воркера зелёные.

Граф импортов снят по всем 76 исходным файлам `src` (без тестов) и 3 файлам `worker/src`. Нарушений
«Целевых правил слоёв» нет; Dexie вне `src/storage` — в `src/hooks/useLiveQuery.ts` и
`src/push/sync.ts` (`liveQuery`), `date-fns` вне домена нет.

## R1. Прежний тест изоляции домена: заменить или оставить

**Decision**: `src/domain/isolation.test.ts` заменяется новым `src/architecture.test.ts` и удаляется в том
же коммите, где новый тест уже зелёный. Каждая прежняя проверка получает соответствие:

| Прежняя проверка (`isolation.test.ts`) | Где после шага |
|----------------------------------------|----------------|
| «has source files to check» (`sources.length > 0`) | «в каждом слое есть файлы» — для всех слоёв, в том числе `domain` |
| Нет `from 'react'`, `'react-dom'`, `'dexie'` | у домена разрешён только пакет `date-fns`; плюс постоянный тест правила: импорт каждого из трёх пакетов доменным файлом даёт нарушение |
| Нет `from '../storage…'`, `'../ui…'`, `'../push…'`, `'../hooks…'` | домену не разрешён ни один слой; плюс постоянный тест правила на эти четыре импорта (а также `report`, `pwa`) |
| Нет `new Date()` и `Date.now(` (регулярное выражение `/new\s+Date\(\s*\)\|Date\.now\(/`) | то же выражение без изменений, для каждого файла домена (R6) |

Новый тест строже: проверяет домен на любой глубине (прежний — только файлы верхнего уровня
`src/domain`), видит импорты без `from`, динамические и повторные экспорты, а пакет вида `react/…` тоже
считается React.

**Rationale**: файл шага разрешает замену «без потери ни одной его проверки», а цель шага — одна таблица
правил. Два теста с правилами домена разошлись бы при первом изменении. Постоянные тесты правила на
прежние семь запретов доказывают сохранность и после того, как временные нарушения откатаны.

**Alternatives considered**: оставить `isolation.test.ts` рядом — ноль правок существующих тестов, но
правила домена в двух местах, причём прежнее выражение слабее. Отклонено: файл шага явно допускает
замену, а дублирование — то, от чего шаг избавляет.

## R2. Как распознавать импорты

**Decision**: разбор синтаксиса TypeScript: `ts.createSourceFile` из пакета `typescript` (уже
dev-зависимость, 5.9.3; в тесте — `import ts from 'typescript'`, проверено). Обход дерева собирает имена
модулей:

- `ImportDeclaration` — `import … from '…'`, `import type …`, `import '…'`;
- `ExportDeclaration` с именем модуля — `export … from '…'`, `export * from '…'`, `export type … from '…'`;
- вызов `import(…)` — динамический импорт; не строковый аргумент даёт имя `import(…)` (R5);
- `ImportTypeNode` — тип вида `import('…').T`;
- `ImportEqualsDeclaration` с внешней ссылкой и вызов `require('…')` — на случай CommonJS-формы.

Комментарии, строки, шаблонные строки и регулярные выражения разбирает сам компилятор, поэтому «импорт» в
комментарии или строке не считается. Директивы `/// <reference …>` — не импорт (`src/vite-env.d.ts`).

**Rationale**: регулярное выражение по тексту видит импорт в комментарии и в строке и плохо переносит
многострочные формы. Самодельный разбор спотыкается о регулярные выражения в коде (`/'/`). Компилятор
уже стоит в проекте и даёт точный ответ: новой зависимости нет (Конституция V). Разбор 79 файлов — доли
секунды.

**Alternatives considered**: `ts.preProcessFile` — тоже без регулярных выражений, но молча пропускает
динамический импорт с вычисляемым именем, а его нужно ловить. Регулярные выражения с вырезанием
комментариев — отклонены по причинам выше. ESLint (`import/no-restricted-paths`) — исключён планом
рефакторинга.

**Не распознаётся**: `import.meta.glob(…)` и `new URL('…', import.meta.url)` (формы Vite). В исходниках
их нет (`new URL` в `sw.ts` строит адрес страницы, а не модуля). Записывается находкой в журнал: при
появлении — добавить форму в распознавание.

## R3. Таблица слоёв

**Decision**: семантика — **список разрешённого**: всё, что не разрешено явно, запрещено. Колонка «Может
импортировать» плана рефакторинга — источник таблицы; колонка «Не может» — пояснение. Где колонки
молчат (`push → pwa`, `hooks → pwa`), запрет следует из списка разрешённого; текущий код ему
соответствует. Импорт внутри своего слоя разрешён всегда.

| Слой (путь) | Разрешённые слои | Разрешённые пакеты |
|-------------|------------------|--------------------|
| `src/domain` | — | `date-fns` |
| `src/storage` | `domain` | `dexie` |
| `src/report` | `domain` | — |
| `src/push` | `domain`, `storage` | — |
| `src/hooks` | `domain`, `storage` | `react` |
| `src/pwa` | — | `virtual:pwa-register` |
| `src/ui` | `domain`, `storage`, `report`, `push`, `hooks`, `pwa` | `react`, `react-dom` |
| `src/main.tsx` | все слои приложения | `react`, `react-dom` |
| `src/sw.ts` | `pwa` | `workbox-core`, `workbox-precaching` |
| `src/vite-env.d.ts` | — | — |
| `worker/src` | — | — |

- `src/main.tsx` — точка сборки: подключает обновления, нормализацию, синхронизацию, интерфейс и CSS.
- `src/sw.ts` — service worker, отдельная сборка (`tsconfig.sw.json`): только разбор push-данных из `pwa`.
- `src/vite-env.d.ts` — объявления типов, импортов нет.
- `worker/src` — отдельный пакет без runtime-зависимостей (`CLAUDE.md`): только свои файлы.
- `react-dom` в `src/ui` нужен `src/ui/testing.ts` (обвязка тестов, `react-dom/client`); интерфейсу он
  разрешён целиком — это его библиотека.

Dexie вне хранилища — не разрешение слоя, а два исключения по файлам (R5): файл шага требует «`dexie` —
только в `storage`, `hooks/useLiveQuery.ts` и там, где это останется после шага 5».

**Rationale**: список разрешённого ловит и то, о чём таблица плана не подумала (новый пакет, новый
слой). Новый пакет в коде без строки в таблице даёт красный тест — это совпадает с правилом «новая
runtime-зависимость — только с обоснованием в плане».

**Alternatives considered**: список запрещённого по колонке «Не может» — пропускает всё неназванное
(новый пакет, `push → pwa`). Отклонено.

## R4. К чему относится импорт

**Decision**:

- Имя, начинающееся с `.`, — относительный путь. Он разрешается от каталога файла
  (`path.posix`, разделители Windows заменяются на `/`). Результат относится к слою с самым длинным
  совпадающим префиксом пути: каталожный слой — по `src/domain/…`; файловый (`src/main.tsx`) — по пути без
  расширения. Импорт вне всех слоёв (например, `../package.json`) — цель «вне слоёв», запрещена.
- Имя, начинающееся с `/`, — запрещено (абсолютный путь).
- Остальное — пакет: `@scope/name/…` → `@scope/name`, `name/…` → `name`; `node:fs`,
  `virtual:pwa-register` — целиком.
- Импорт CSS (`./ui/theme.css` в `main.tsx`) — зависимость от слоя `ui`.

**Rationale**: `../domain/x` из `src/storage` и `../../domain/x` из `src/storage/migrations` относятся к
одному слою; подпуть пакета (`date-fns/locale`, `react-dom/client`) — к своему пакету.

## R5. Исключения

**Decision**: исключение — запись `{ file, target, reason }`, где `target` — пакет или слой (или
`import(…)` для вычисляемого динамического импорта). Исключение разрешает только этот импорт только в
этом файле. Отдельный тест на каждое исключение проверяет, что файл действительно импортирует `target`;
иначе — «исключение больше не нужно, удалите его».

Исключения на текущем коде — два:

| Файл | Импорт | Причина |
|------|--------|---------|
| `src/hooks/useLiveQuery.ts` | `dexie` | живые запросы: своя обёртка над `liveQuery` вместо `dexie-react-hooks` (Конституция V); единственный хук с Dexie |
| `src/push/sync.ts` | `dexie` | `startReminderSync` подписывается `liveQuery(reminderDataQuery)`, чтобы отправить расписание после изменения данных; осталось после шага 5 (018 R7) |

Импорт типа `notificationPermission` из `push` в `src/ui/components/reminderToggle.ts` исключением не
является: интерфейсу `push` разрешён. Контрактный тест воркера импортирует `src/domain` и `src/pwa`, но
тесты не проверяются (FR-009) — это названное исключение шага 5, оно описано в карте архитектуры.

**Rationale**: файл шага требует перечислять исключения явно и с причиной, а не ослаблять распознавание.
Проверка «исключение ещё нужно» не даёт таблице обрастать мёртвыми строками.

## R6. Чтение часов в домене

**Decision**: прежнее выражение `/new\s+Date\(\s*\)|Date\.now\(/` применяется к тексту каждого файла
домена (на любой глубине) без изменений — отдельным `it.each`.

**Rationale**: так проверка сохраняется буквально (R1). Перевод на разбор дерева изменил бы её
поведение (например, в комментариях) — это не цель шага.

## R7. Как показать, что тест падает на нарушении

**Decision**: в ходе реализации — временные файлы `__violation.ts` в каталоге слоя (для `src/sw.ts` —
временная строка в самом файле, откат `git checkout -- src/sw.ts`). После проверки они удаляются; в
репозиторий не попадают (перед коммитом — `git status` и `git diff`). Существующие исходники, кроме
`sw.ts` на время одной проверки, не трогаются. Сценарии (SC-003):

| Где | Временное нарушение | Ожидаемое правило в сообщении |
|-----|---------------------|-------------------------------|
| `src/domain` | `import '../ui/app.css'`; отдельно `export { db } from '../storage/db'`; многострочный `import {…} from 'react'`; `const m = import('../push/sync')`; `Date.now()` | слой `domain` не может импортировать `ui` / `storage` / пакет `react` / `push`; чтение часов |
| `src/storage` | `import type { App } from '../ui/App'` | `storage` не может импортировать `ui` |
| `src/report` | `import { getPeriods } from '../storage/repository'`; `import 'dexie'` | `report` → `storage`; пакет `dexie` |
| `src/push` | `import { useToday } from '../hooks/useToday'` | `push` → `hooks` |
| `src/hooks` | `import { syncReminders } from '../push/sync'` | `hooks` → `push` |
| `src/pwa` | `import { getSettings } from '../storage/repository'` | `pwa` → `storage` |
| `src/ui` | `import { format } from 'date-fns'` | пакет `date-fns` |
| верхний уровень `src` | новый файл `src/extra.ts`; в `sw.ts` — `import './ui/App'` | файл вне таблицы; `sw` → `ui` |
| `worker/src` | `import { toLocalDate } from '../../src/domain/dates'` | `worker` → `domain` |
| исключение | временно убрать `liveQuery` из `push/sync.ts` нельзя (код не меняется) — вместо этого временная строка исключения для файла без такого импорта | «исключение больше не нужно» |

Результаты (сообщение красного теста) записываются в журнал задач.

## R8. Сообщение и устройство теста

**Decision**: чистая функция `violations(file, text)` возвращает список строк вида
`src/storage/x.ts: '../ui/App' — слой storage не может импортировать слой ui`. Тест на файл —
`it.each(files)('%s — по правилам слоя', …)` с `expect(violations(...)).toEqual([])`: Vitest показывает
список нарушений целиком. Отдельные `describe`: распознавание (образцы текста), отнесение к слою и пакету,
правила (включая прежние запреты домена), исключения, часы, файлы и слои, карта архитектуры.

Тестов на файл — 79 (76 в `src` + 3 в `worker/src`), часов — 19, непустых слоёв — 11, исключений — 2,
плюс образцы. Прежний тест давал 39 (1 + 2 × 19). Итог — больше базовых 1348.

**Rationale**: имя файла в названии теста и строка нарушения дают «файл, импорт и правило» (FR-007) без
дополнительного кода.

## R9. Проверка карты архитектуры тестом

**Decision**: в том же `src/architecture.test.ts`, `describe('карта архитектуры')`:

1. `docs/architecture.md` существует и не длиннее 120 строк.
2. Есть разделы: `## Слои`, `## Пути данных`, `## Правила корректности данных`, `## Чек-листы` с
   подразделами `### Добавить настройку`, `### Добавить отметку дня`, `### Добавить вид напоминания`;
   есть ссылка на `src/storage/migrations/README.md`.
3. Каждый путь проекта в обратных кавычках существует. Путь — фрагмент, начинающийся с `src/`, `docs/`,
   `worker/`, `specs/`, `.specify/` или равный `CLAUDE.md`, `README.md`, `package.json`,
   `vitest.config.ts`, `.gitignore`. Фрагменты с `*`, `…`, `<`, `{` (шаблоны) пропускаются. Суффикс
   `:строка` не допускается — карта не ссылается на номера строк, они устаревают.
4. Первые ячейки таблицы раздела «Слои» (пути в обратных кавычках) совпадают с путями слоёв таблицы теста —
   те же 11, ни больше ни меньше.

Тест пишется до документа и падает (документа нет).

**Rationale**: «соответствует коду» (критерий готовности) проверяется хотя бы на уровне путей и слоёв;
остальное — сверка при написании (R10). Разрешённые зависимости в документе не дублируются построчно:
таблица документа пересказывает правила коротко и ссылается на тест как на точный источник.

## R12. Артефакты сборки в git

**Decision**: `git rm --cached tsconfig.tsbuildinfo`; в `.gitignore` — строка `*.tsbuildinfo`. Файл на

## R13. Настройки тестов

**Decision**: в `vitest.config.ts` убирается `passWithNoTests: true`; `include` становится
`['src/**/*.test.ts', 'src/**/*.test.tsx']`. Без `passWithNoTests` Vitest при пустом поиске завершается с
кодом 1 («No test files found»). `tsconfig.json` уже включает `src` — файлы `*.test.tsx` проверяются
типами. У воркера (`worker/vitest.config.ts`) `passWithNoTests` нет — правка не нужна.

**Rationale**: журнал шага 6 отложил `*.test.tsx` сюда «вместе с `passWithNoTests`»; без этого файл
`*.test.tsx` не запустился бы молча.

## R14. Другие тесты, читающие исходники, не объединяются

**Decision**: `derivationPlacement`, `explanationTexts` (домен), `uiLogicPlacement`, `dayWrites`
(интерфейс), `validationPlacement` (хранилище), `pushPlacement`, контрактный тест воркера остаются как
есть. Частично они повторяют правила слоёв (`uiLogicPlacement`: нет `date-fns` в `src/ui`;
`contract.test.ts`: `worker/src` не импортирует код приложения), но их объединение изменило бы
существующие проверки (общее ограничение 2) и не входит в пункты 1–4 наброска. В журнал: повторы
безвредны; объединить — отдельным решением пользователя.

## R15. Импорт только типов

**Decision**: считается зависимостью, как обычный. На текущем коде это не даёт нарушений: все импорты
типов идут по разрешённым направлениям (например, `ui → push` в `reminderToggle.ts`, `ui → domain`).

**Rationale**: связь через типы — тоже связь; пример исключения в файле шага («тип из `storage` в
`push`») предполагает именно такой учёт.
