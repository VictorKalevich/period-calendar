# Data Model: Запись дня — точечным изменением в транзакции

Хранимые данные не меняются: `SCHEMA_VERSION = 6`, таблицы `periods`, `days`, `kv`, форма записей и
формат резервной копии — прежние (FR-015). Новое — только тип изменения, который не хранится.

## Запись дня (`DayEntry`, хранится в `db.days`, ключ `date`) — без изменений

| Поле | Тип | Правило (009, приведение `coerceDayEntry`) |
|------|-----|--------------------------------------------|
| `date` | `LocalDate` (`YYYY-MM-DD`) | обязательна и корректна; иначе запись отклоняется |
| `symptoms` | `SymptomId[]` | известные коды, без повторов, в порядке справочника |
| `intensity` | `Partial<Record<SymptomId, Intensity>>` | только у отмеченных пунктов |
| `moods` | `MoodId[]` | известные коды (и старые коды v1–v9), без повторов, по справочнику |
| `sex` | `boolean` | `true` только при `=== true` |
| `note` | `string` | без пробелов по краям, не длиннее 1000 символов |

Пустая запись (нет пунктов самочувствия, настроений, отметки секса и заметки) не хранится.

## Изменение записи дня (`DayEntryPatch`) — новое, не хранится

`DayEntryPatch = Partial<Omit<DayEntry, 'date'>>`. Дата передаётся отдельно и накладывается последней.

| Источник | Изменение |
|----------|-----------|
| Лист «Самочувствие» | `{ symptoms, intensity }` — пункты и степени из листа |
| Лист «Настроение» | `{ moods }` |
| Лист «Заметки» (сохранить / удалить) | `{ note }` (удаление — `{ note: '' }`) |
| Отметка секса в диалоге дня | `{ sex }` — значение по надписи кнопки (research R2) |

## Переходы записи дня при `updateDayEntry(date, patch)`

Всё — в одной транзакции `rw` по `db.days`.

| Было в базе | Результат `coerce({ ...было или пустая, ...patch, date })` | Стало |
|-------------|------------------------------------------------------------|-------|
| нет записи | непустой | запись создана: изменённые поля, остальные пустые |
| нет записи | пустой | записи нет (ничего не пишется, кроме удаления несуществующей) |
| запись (в т. ч. старой формы — мягкое чтение) | непустой | запись обновлена: изменённые поля новые, остальные как были (после приведения) |
| запись | пустой | запись удалена |
| любое | дата некорректна | ошибка, база не меняется |
| любое | отказ записи базы | ошибка, транзакция отменена, запись прежняя целиком |

## Запись выбранного дня на экране «Календарь»

| Состояние | Значение запроса (`stored`) | Что получают карточка, диалог и листы (`entry`) |
|-----------|-----------------------------|----------------------------------------------|
| ответ для выбранного дня пришёл | запись дня `day` или `undefined` | то же значение |
| день сменился, ответ ещё не пришёл | запись прежнего дня (хук держит прежнее значение) | `undefined` («записи нет») |

Правило: `entry = stored?.date === day ? stored : undefined` (research R3).

## Нормализация месячных при запуске

Одна транзакция `rw` по `db.periods` и `db.kv`: чтение месячных и настроек → `buildForecast` →
`normalizePeriods` → запись (только если что-то объединилось). Результат и признак «изменено» —
прежние (003 FR-016).
