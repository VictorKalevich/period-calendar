# Фича 008: импорт месячных из текстового файла

**Статус**: реализовано · **Дата**: 2026-11-09

## Задача

Пользовательница переносит историю из другого приложения, которое выгружает текстовый файл вида:

```
cycle 0
Period start date: 2017-12-23 20:00:00.0
Period end date: 2017-12-27 20:00:00.0
Pregnant: False
Period intensity:
Day 1: intensity: Medium
---------------
…
manual events
0 - 2018-01-06 20:00:00 - 2018-01-06 20:00:00 - Symptom - Fatigue -
```

## Требования

- **FR-001** Из файла берутся только пары «Period start date:» / «Period end date:» блоков «cycle N».
  Дата — часть `YYYY-MM-DD` как есть; время суток отбрасывается, часовые пояса не пересчитываются.
  Блок «manual events» и прочие поля (Pregnant, intensity) игнорируются.
- **FR-002** Блок пропускается и учитывается в отчёте, если: нет корректного начала; конец некорректен
  или раньше начала; начало в будущем; длина больше 15 дней; конец не указан, а блок не последний или
  начался 15 и более дней назад. Конец в будущем превращается в «ещё идут» (конец не отмечен).
- **FR-003** Периоды файла нормализуются между собой: дубли и пересечения внутри файла объединяются.
- **FR-004** Данные из файла в приоритете. Существующие месячные, которые пересекаются с периодом файла
  или идут вплотную к нему (по оценочному концу для незакрытых), удаляются целиком; периоды файла
  добавляются со своими датами без изменений. Остальные существующие месячные не меняются.
- **FR-005** Существующие месячные с теми же датами, что в файле, сохраняются (конец становится
  отмеченным) — повторный импорт того же файла ничего не меняет.
- **FR-006** Заметки, самочувствие, настройки и состояние push не меняются.
- **FR-007** Настройки → «Резервная копия» → «Импорт» принимает `.json` и `.txt`. Формат определяется
  по содержимому: JSON — восстановление резервной копии, как раньше; текст с «Period start date:» —
  этот импорт; иначе «Файл не распознан».
- **FR-008** Перед сохранением — подтверждение «Добавить месячные?»: «Найдено: N периодов месячных
  (ДД.ММ.ГГГГ – ДД.ММ.ГГГГ)», при M > 0 — «Будут заменены уже отмеченные месячные: M периодов»,
  при пропусках — их число. После — «Добавлено: N периодов месячных» или «Все месячные из файла уже
  были отмечены».

## Реализация

- `src/domain/cycleText.ts` — `parseCycleText(text, today)` и `mergeImportedPeriods(...)`, чистые функции.
- `src/storage/textImport.ts` — `planTextImport` (ничего не сохраняет) и `applyTextImport`.
- `src/ui/components/BackupSection.tsx` — выбор формата, лист подтверждения.
- Тесты: `src/domain/cycleText.test.ts`, `src/storage/textImport.test.ts`.

## Проверка

На реальной выгрузке (100 блоков, 23.12.2017 – 25.10.2026): прочитано 100, пропущено 0; дубль
05–09.01.2025 / 05–13.01.2025 объединён → 99 месячных. Проверено в браузере (390×844): лист
подтверждения, сообщение «Добавлено: 99 периодов месячных», прогноз в календаре.
