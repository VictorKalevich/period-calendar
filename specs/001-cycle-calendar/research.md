# Research: Календарь цикла

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-23

Стек задан пользователем: Vite + React + TypeScript, vite-plugin-pwa, Dexie, date-fns, Vitest,
GitHub Pages + GitHub Actions, Cloudflare Worker для Web Push. Ниже — решения по открытым вопросам
внутри этого стека.

## R1. Представление дат в домене

- **Decision**: календарная дата — строка `YYYY-MM-DD` (тип `LocalDate`, branded string). Арифметика —
  через date-fns (`addDays`, `differenceInCalendarDays`) над `Date`, созданным как локальная полночь
  (`parseISO('2026-03-01')`), результат сразу форматируется обратно в `YYYY-MM-DD`.
  «Сегодня» в домен передаётся параметром.
- **Rationale**: строки однозначны, сортируются лексикографически, безопасно сериализуются в
  IndexedDB/JSON и не зависят от часового пояса. `differenceInCalendarDays` корректна при переходе
  на летнее время (Конституция IV).
- **Alternatives**: `Date` в хранилище (сдвиги при смене пояса); Temporal API (нет в iOS Safari без
  полифила); номера дней от эпохи (неудобно отлаживать).

## R2. Свайп месяцев (pager)

- **Decision**: нативный горизонтальный контейнер с `scroll-snap-type: x mandatory` и
  `scroll-snap-stop: always`; страница = месяц шириной 100%. Диапазон страниц: от (первая отметка −
  12 мес., но не позже текущего − 12) до (текущий + 12 мес.). Сетка дней рендерится только для
  текущей и соседних страниц (по `IntersectionObserver`), остальные — пустые плейсхолдеры той же
  ширины. Кнопки «‹ ›» вызывают `scrollTo({ left, behavior: 'smooth' })`. Активный месяц определяется
  по `IntersectionObserver` (порог 0.6), а не по событию `scrollend`.
- **Rationale**: нулевые зависимости, нативная инерция и «пружина» iOS — ощущение как у Android
  ViewPager; без перецентрирования окна из 3 страниц, которое на iOS даёт мерцание.
- **Alternatives**: библиотека жестов (`@use-gesture/react` + анимации) — лишняя зависимость,
  ручная физика; окно из 3 страниц с перецентрированием — мерцание и прыжки скролла на iOS.

## R3. Хранилище и миграции

- **Decision**: Dexie, база `cycle-calendar`. Версии схемы через `db.version(n).stores(...).upgrade()`;
  каждая миграция — отдельная функция в `src/storage/migrations/`, покрыта тестом на `fake-indexeddb`
  (dev-зависимость). При старте вызывается `navigator.storage.persist()`.
- **Rationale**: Dexie берёт на себя версионирование IndexedDB; PWA на экране «Домой» не подпадает под
  7-дневную очистку ITP, `persist()` — дополнительная защита (Конституция III).
- **Alternatives**: «голый» IndexedDB (больше кода), `idb` (нет встроенных миграций),
  localStorage (лимиты, синхронный, нет схемы).

## R4. Service Worker и офлайн

- **Decision**: vite-plugin-pwa в режиме `injectManifest` с собственным `src/sw.ts`: Workbox
  precache всех ассетов + обработчики `push` и `notificationclick`. `registerType: 'autoUpdate'`,
  `base: '/period-calendar/'` (путь GitHub Pages проекта).
- **Rationale**: `generateSW` не позволяет добавить обработчик push; `injectManifest` оставляет
  офлайн-кэш на плагине. Данные живут в IndexedDB, поэтому обновление SW их не трогает.
- **Alternatives**: `generateSW` + `importScripts` — хрупко; SW без Workbox — ручное версионирование кэша.

## R5. Web Push на iOS

- **Decision**: стандартный Web Push (VAPID) для PWA на экране «Домой», iOS 16.4+. Подписка
  создаётся только по нажатию пользовательницы («Включить напоминания») после
  `Notification.requestPermission()`. Если `navigator.standalone !== true` — показывается инструкция
  «Поделиться → На экран „Домой“».
- **Rationale**: единственный бесплатный путь доставки уведомлений при закрытом приложении без
  нативной сборки (Конституция II).
- **Alternatives**: локальные уведомления по таймеру в SW — на iOS не работают при закрытом приложении;
  Periodic Background Sync — не поддерживается Safari.

## R6. Расписание отправки в Cloudflare Worker

- **Decision**: Cron Trigger **каждый час в :00** (`0 * * * *`) вместо ежедневного. Клиент присылает
  готовые напоминания с абсолютным моментом отправки `sendAt` (UTC), вычисленным на устройстве как
  «12:00 по местному времени в нужную дату». Cron отправляет все напоминания с `sendAt <= now` и
  удаляет их.
- **Rationale**: ежедневный cron срабатывает в одно фиксированное UTC-время и не может попасть в 12:00
  по местному времени для любого пояса; почасовой cron даёт точность в пределах минут (SC-005) и
  укладывается в бесплатный тариф (24 вызова/сутки). Часовой пояс устройства не передаётся на сервер.
- **Alternatives**: ежедневный cron (не попадает в 12:00); cron каждые 5 минут (избыточно — оба
  напоминания ровно в 12:00); Durable Object alarms (сложнее, нужен платный тариф).

## R7. Хранение на стороне Worker

- **Decision**: Workers KV, один ключ на устройство: `sub:{clientId}` →
  `{ tokenHash, subscription, reminders[] }`. Cron перечисляет ключи (`list`) — для одной
  пользовательницы это единицы записей.
- **Rationale**: бесплатный тариф KV с запасом покрывает нагрузку; данных минимум (Конституция I).
- **Alternatives**: D1 (SQL избыточен для одной записи); Durable Objects (сложнее).

## R8. Шифрование Web Push в Worker

- **Decision**: собственная реализация RFC 8291 (aes128gcm) и RFC 8292 (VAPID JWT ES256) на WebCrypto,
  ~150 строк, тесты на векторах из RFC 8291 Appendix A.
- **Rationale**: пакет `web-push` зависит от Node `crypto` и не работает в Workers; собственная
  реализация без зависимостей соответствует Конституции V и полностью проверяема тестами.
- **Alternatives**: сторонние WebCrypto-обёртки для Web Push — запасной вариант, если реализация
  не пройдёт тестовые векторы или реальную доставку на iPhone.

## R9. Защита API Worker без аккаунтов

- **Decision**: при первом включении напоминаний клиент генерирует `clientId` (UUID) и `token`
  (32 случайных байта, base64url), хранит их в IndexedDB. Все запросы — `Authorization: Bearer
  {token}`; Worker хранит только SHA-256 токена, первая запись по новому `clientId` создаёт его.
  CORS разрешён только для origin GitHub Pages. Размеры тела и число напоминаний ограничены.
- **Rationale**: без аккаунтов, но чужой не может перезаписать или удалить подписку.
- **Alternatives**: открытый API (можно спамить чужую подписку при знании clientId); аккаунты —
  запрещены Конституцией I.

## R10. Синхронизация расписания напоминаний

- **Decision**: клиент после любого изменения отметок/настроек (с debounce 2 с) и при каждом запуске
  приложения пересчитывает напоминания на ближайшие 6 прогнозируемых циклов и делает идемпотентный
  `PUT` полного списка. Если офлайн — флаг `pendingSync` в IndexedDB, повтор при событии `online`
  и при следующем запуске.
- **Rationale**: полная замена списка исключает рассинхрон и «старые» напоминания (сценарий 4 US4);
  6 циклов вперёд покрывают долгие перерывы в открытии приложения.
- **Alternatives**: инкрементальные add/delete — сложнее и хрупко.

## R11. Резервная копия на iPhone

- **Decision**: экспорт — `navigator.share({ files: [File] })` (меню «Поделиться» → «Сохранить в
  Файлы»), при отсутствии поддержки — скачивание через `<a download>`. Импорт — `<input type="file"
  accept="application/json,.json">`, ручная валидация структуры (без библиотек схем), затем миграция
  до текущей версии и замена данных в одной транзакции.
- **Rationale**: штатные механизмы iOS, без зависимостей.
- **Alternatives**: zod/valibot для валидации — лишняя зависимость ради одного формата.

## R12. UI без библиотек компонентов

- **Decision**: React без роутера — 4 вкладки как состояние приложения (активная вкладка в
  `location.hash` для восстановления); стили — обычный CSS с токенами в CSS-переменных и
  `@media (prefers-color-scheme: dark)`; карточка дня — нижний лист (bottom sheet) на `<dialog>`.
  Форматирование дат — date-fns с локалью `ru`. Учитываются `env(safe-area-inset-*)`.
- **Rationale**: минимум зависимостей (Конституция V), темы и контраст под контролем (Конституция VI).
- **Alternatives**: react-router, UI-киты, CSS-in-JS — не нужны для 4 экранов.

## R13. Деплой

- **Decision**: GitHub Actions: на push в `main` — `npm ci`, `npm test`, `npm run build`,
  `actions/upload-pages-artifact` + `actions/deploy-pages`. Worker деплоится вручную `wrangler deploy`
  (секреты VAPID через `wrangler secret put`). Публичный VAPID-ключ и URL Worker — переменные сборки
  `VITE_VAPID_PUBLIC_KEY`, `VITE_PUSH_API_URL`.
- **Rationale**: бесплатно, каждый коммит в `main` проверяется тестами (Конституция V).
