# Новая версия схемы хранения — чек-лист

Конституция III: обновление приложения никогда не теряет данные. Любое изменение схемы IndexedDB
или формы хранимых записей делается так:

1. Увеличить `SCHEMA_VERSION` в `src/storage/db.ts` (было N, стало N + 1).
2. Добавить `this.version(N + 1).stores({...}).upgrade(tx => ...)` в `CycleDb`. Старые версии
   не удалять и не менять.
3. Добавить `migrations[N]` в `index.ts` — чистую функцию над объектом данных
   `{ periods, days, settings }`, той же логикой, что в `upgrade`. Она применяется к импорту
   резервных копий старых версий.
4. Миграция:
   - идемпотентна (повторный запуск ничего не портит);
   - не удаляет поля и записи, которые не умеет преобразовать;
   - задаёт значения по умолчанию для новых обязательных полей.
5. Тесты (сначала тест — потом код):
   - `migrations.test.ts` — `migrateData(dataN, N, N + 1)` на реальном примере данных версии N;
   - тест открытия базы версии N новой сборкой (по образцу `update.test.ts`);
   - `backup.test.ts` — импорт файла с `schemaVersion: N`.
6. Обновить `contracts/backup-format.md` и `data-model.md` фичи.
