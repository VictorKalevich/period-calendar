# Шаг 8. Выпуск: слияние в `main`, деплой, push

Последний шаг. Единственный, где разрешены `git push origin main` и `npx wrangler deploy`.
Spec Kit здесь не используется: новой функциональности нет, только выпуск накопленного.
Общие правила — `docs/refactoring-roadmap.md`.

Запуск этого шага пользователем — и есть разрешение на push в `main`. Push запускает сборку и
деплой на GitHub Pages.

## Порядок выпуска

Команды `npm …` — из PowerShell в папке проекта. При любом красном результате или конфликте —
остановиться, ничего не отправлять, сообщить пользователю.

1. **Готовность.** В таблице плана каждый шаг 1–7 имеет статус `выполнен` или `исключён`. Есть
   шаг `не начат` или `в работе` — остановиться и спросить пользователя: исключить его или
   выполнить сначала. Если все шаги 1–7 исключены, выпускать нечего: сообщить и остановиться.
2. **Состояние веток.** `git switch refactoring`; рабочее дерево чистое (папка `Claude outputs/`
   не в счёт). `git fetch origin`. Если `origin/main` впереди локального `main` — обновить `main`
   (`git switch main`, `git merge --ff-only origin/main`, `git switch refactoring`). Если `main`
   содержит коммиты, которых нет в `refactoring`, — `git merge main` в `refactoring`.
3. **Полная проверка в `refactoring`:**
   - `npm test`
   - `npm run build`
   - `npm test --prefix worker`
   - `npm run typecheck --prefix worker`

   Число тестов не меньше базового из «Журнала» плана (приложение 584, воркер 37).
4. **Просмотр суммарных изменений:** `git log --oneline main..refactoring` и
   `git diff --stat main...refactoring`. Проверить `git diff main...refactoring` на испорченную
   кириллицу (вида «РќР°…», «Ð…») и BOM. Убедиться, что не изменены `SCHEMA_VERSION` и блоки
   `this.version(…)` в `src/storage/db.ts`, `worker/wrangler.toml`, `.github/workflows/deploy.yml`.
   Неожиданное изменение — остановиться и сообщить.
5. **Сводка пользователю перед отправкой** (сообщением, без ожидания ответа): выполненные и
   исключённые шаги, число коммитов, результаты проверок, нужен ли деплой воркера.
6. **Статус в плане.** Поставить шагу 8 статус `выполнен`, добавить строку в «Журнал» (дата,
   число тестов, список вошедших шагов). Закоммитить в `refactoring`.
7. **Воркер.** Если `git diff --name-only main...refactoring -- worker/src worker/wrangler.toml`
   не пуст — из папки `worker` выполнить `npx wrangler deploy`, до push. Ошибка деплоя —
   остановиться, `main` не трогать. Секреты воркера не перезагружать.
8. **Слияние и push:**
   - `git switch main`
   - `git merge --no-ff refactoring`
   - `npm test` и `npm run build` ещё раз, на `main`
   - `git push origin main`
9. **Сборка в GitHub Actions.** `gh` не установлен — статус смотреть по адресу
   `https://api.github.com/repos/VictorKalevich/period-calendar/actions/runs?branch=main`:
   дождаться завершения запуска «Test and deploy to GitHub Pages» для отправленного коммита.
10. **Завершение.**
    - Сборка успешна — `git branch -d refactoring`; если ветка есть на origin —
      `git push origin --delete refactoring`. Сообщить пользователю: что вышло, адрес запуска
      Actions, был ли задеплоен воркер.
    - Сборка упала — ветку не удалять; сообщить пользователю причину. Исправление — новым
      коммитом, статус шага 8 вернуть в `в работе`.

## Ручная проверка после деплоя (пользователь)

Рефакторинг не должен ничего менять, поэтому достаточно убедиться, что всё на месте:

- приложение открывается с иконки, внизу «Настроек» — номер новой сборки;
- прежние отметки месячных, записи дней и настройки на месте;
- отметить и снять запись дня (самочувствие, настроение, заметка, отметка секса);
- «Статистика» → «Отчёт» создаёт PDF;
- «Настройки» → «Экспорт» отдаёт файл;
- если выполнялся шаг 5 — «Для разработчика» → «Проверить уведомление» (режим разработчика:
  7 нажатий на версию).

## Критерии готовности

- `origin/main` содержит все выполненные шаги; запуск Actions для этого коммита успешен.
- Если менялся `worker/src` — воркер задеплоен до push.
- Ветка `refactoring` удалена локально и на origin (если была там).
- В плане шаг 8 — `выполнен`, «Журнал» дополнен.
