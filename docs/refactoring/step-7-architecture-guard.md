# Шаг 7. Правила слоёв под тестом, карта архитектуры, гигиена репозитория

Приоритет: низкий. Выполняется после шагов 1–6 (описывает итоговую структуру).
Видимых изменений нет.
Общие правила и порядок работы — `docs/refactoring-roadmap.md`.

## Проблема

1. **Тестом охраняется только домен.** `src/domain/isolation.test.ts` запрещает домену импортировать
   `react`, `dexie`, `storage`, `ui`, `push`, `hooks` и читать часы. Для остальных слоёв правил в
   коде нет: ничто не мешает `storage` импортировать `ui`, а `report` — `storage`. Сейчас граф
   чистый (проверено 2026-11-14), но держится на внимательности.
2. **Сам тест домена неполон**: регулярное выражение не знает слоёв `report` и `pwa`, не видит
   импорты без `from` (`import './x'`) и динамические `import()`.
3. **Нет актуального описания архитектуры.** Сведения разнесены по 13 каталогам `specs/NNN-…`
   (около 3 600 строк только в spec, plan и data-model), и часть уже устарела. `CLAUDE.md`
   называет текущей фичей `specs/001-cycle-calendar/`.
4. **Добавление одной настройки требует правок в шести местах**, и список нигде не записан: тип и
   значение по умолчанию (`src/domain/types.ts`), миграция (`src/storage/migrations/index.ts`),
   версия и `upgrade` (`src/storage/db.ts`), правило поля для импорта, экран настроек, тесты
   миграции, обновления и резервной копии. Пять из шести версий схемы — именно такие изменения.
5. **Гигиена:**
   - `tsconfig.tsbuildinfo` отслеживается в git (последнее изменение — фича 007), в `.gitignore`
     его нет;
   - `passWithNoTests: true` (`vitest.config.ts:11`) скроет ошибку в шаблоне поиска тестов;
   - запуск тестов из Git Bash с `cd /c/…` падает целиком («Vitest failed to find the runner») —
     в `CLAUDE.md` об этом ни слова.

## Цель

Правила слоёв из плана проверяются тестом; у проекта есть одна короткая актуальная карта
архитектуры; репозиторий не хранит артефакты сборки.

## Набросок решения

1. **`src/architecture.test.ts`**: таблица «слой → разрешённые зависимости» из раздела «Целевые
   правила слоёв» плана; проверка всех файлов `src/**` (кроме тестов); ловит `import … from`,
   `import '…'`, `export … from`, `import()`. Отдельные правила: `date-fns` — только в `domain`;
   `dexie` — только в `storage`, `hooks/useLiveQuery.ts` и там, где это останется после шага 5;
   чтение часов запрещено в `domain`. `isolation.test.ts` либо заменяется этим тестом, либо
   остаётся — но без потери ни одной его проверки.
2. **`docs/architecture.md`** (коротко, до двух экранов): слои и их правила; пути данных — чтение
   через `liveQuery`, запись, синхронизация напоминаний, обновление PWA, отчёт; где живут правила
   корректности данных; чек-листы «добавить настройку», «добавить отметку дня», «добавить вид
   напоминания»; ссылка на `src/storage/migrations/README.md`.
3. **`CLAUDE.md` и `README.md`**: ссылка на `docs/architecture.md`; убрать устаревшую «Текущую
   фичу»; в «Команды» — строка о запуске тестов из PowerShell.
4. **Гигиена**: `git rm --cached tsconfig.tsbuildinfo` и `*.tsbuildinfo` в `.gitignore`; убрать
   `passWithNoTests`.

## Проверить на этапе плана

- Тест архитектуры должен падать на нарушении: показать это временным неверным импортом в ходе
  разработки (красный → зелёный), в репозиторий нарушение не попадает.
- Исключения перечисляются в таблице теста явно и с причиной (например, тип из `storage` в
  `push`), а не ослаблением регулярного выражения.
- `docs/architecture.md` описывает состояние после выполненных шагов: свериться с «Журналом» плана
  и с кодом, не с файлами шагов.
- Правка `CLAUDE.md` — изменение инструкций проекта: показать пользователю итоговый текст в отчёте.

## Границы

Входит: пункты 1–4 наброска.

Не входит: перенос кода между слоями (если тест находит нарушение — остановиться и сообщить, не
чинить в этом шаге), ESLint и другие новые зависимости, правка спецификаций прошлых фич, изменение
правил рабочего процесса в `CLAUDE.md`.

## Критерии готовности

- `src/architecture.test.ts` проверяет все слои и зелёный на текущем коде; все проверки прежнего
  `isolation.test.ts` сохранены.
- `docs/architecture.md` существует, соответствует коду и не длиннее двух экранов.
- `CLAUDE.md` и `README.md` ссылаются на него; устаревшая «Текущая фича» убрана.
- `tsconfig.tsbuildinfo` не отслеживается; `git status` после `npm run build` чистый.
- `npm test` находит не меньше тестов, чем до шага; `npm test` и `npm run build` зелёные.
