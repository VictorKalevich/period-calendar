# Шаг 1. Сбой не оставляет пустой экран

Приоритет: высокий. Зависимости: нет.
Общие правила и порядок работы — `docs/refactoring-roadmap.md`.

**Это единственный шаг с видимыми изменениями**: при сбое появляется аварийный экран и сообщение
об ошибке сохранения. На обычном пути разметка и поведение прежние.

## Проблема

Данные существуют только на устройстве (Конституция III), а при любом сбое пользовательница видит
пустой экран и не может добраться до «Экспорта».

1. **Нет границы ошибок.** `src/ui/App.tsx:46-48` рисует `<Screen />` без `ErrorBoundary`, в
   `src/main.tsx:16-20` его тоже нет. Исключение при отрисовке снимает всё дерево React — страница
   становится пустой.
2. **Ошибка чтения базы проглатывается.** `src/hooks/useLiveQuery.ts:14` только пишет в консоль;
   значение остаётся `undefined`, и экраны навсегда возвращают `null`
   (`CalendarScreen.tsx:39`, `SettingsScreen.tsx:15`, `StatsScreen.tsx:20`). Если IndexedDB не
   открылась, видна только нижняя навигация.
3. **Откуда берутся исключения при отрисовке.** `parseLD` бросает исключение на некорректной дате
   (`src/domain/dates.ts:25-29`), а месячные читаются из базы без проверки
   (`src/storage/repository.ts:21-23`); нечисловая настройка даёт `Invalid Date` в
   `buildForecast` (`src/domain/forecast.ts:82`), и `format` из date-fns бросает `RangeError`.
4. **Ошибки записи не видны.** Обработчики ждут запись без `catch`: `DayDialog.tsx:52`,
   `MoodPicker.tsx:28`, `NoteEditor.tsx:29`, `SymptomPicker.tsx:54`, `DaySheets.tsx:27`,
   `SettingsScreen.tsx:16`, `RemindersSection.tsx:23-38`, `VersionTapper.tsx:20`,
   `FirstPeriodHint.tsx:19`, `BackupSection.tsx:109`. При отказе записи лист остаётся открытым
   без сообщения. Ошибки обрабатывает только импорт (`BackupSection.tsx:69-99`).

## Цель

Любой сбой отрисовки, чтения или записи даёт понятное сообщение и путь к экспорту резервной
копии. На обычном пути ничего не меняется.

## Набросок решения

1. **Сначала `docs/design/design.md`**: описать «Аварийный экран» и «Ошибку сохранения в листе»,
   собранные только из существующих компонентов (`card settings-card`, `t-card-title`, `t-body`,
   `notice notice--error`, `btn btn--primary`, `btn`). Новых классов и токенов не вводить.
2. **Граница ошибок** вокруг экрана вкладки (сбрасывается при смене вкладки) и вторая — вокруг
   всего приложения. Нижняя навигация остаётся рабочей, когда упал один экран.
3. **Аварийный экран**: текст о сбое, кнопки «Экспорт данных» и «Перезагрузить». Экспорт идёт через
   `exportBackup()` (`src/storage/backup.ts:45`) и `shareOrDownload` (`src/ui/components/share.ts`) —
   этот путь не зависит от прогноза и отрисовки. Если база недоступна, экспорт показывает
   `notice notice--error`.
4. **`useLiveQuery` передаёт ошибку границе** (сохраняет её и бросает при отрисовке) вместо
   вечного `undefined`.
5. **Ошибка записи в листах**: лист остаётся открытым и показывает `notice notice--error`, как уже
   делает `DayDialog` для доменных ошибок (`DayDialog.tsx:82-86`). Один общий приём для всех
   обработчиков из п. 4 «Проблемы», а не десять копий `try/catch`.

## Проверить на этапе плана

- Тесты идут в окружении `node` (`vitest.config.ts:9`). Серверная отрисовка React
  (`renderToStaticMarkup`, как в `ForecastInfo.test.ts`) границы ошибок не поддерживает. Варианты:
  тестировать чистые части (разметку аварийного экрана, состояние ошибки `useLiveQuery`, общий
  приём обработки записи) либо обосновать dev-зависимость с DOM (jsdom или happy-dom — не runtime).
- Какие тексты показывать: один общий или разные для сбоя отрисовки и недоступной базы.
- Не скрывает ли граница ошибку от консоли (ошибка должна по-прежнему логироваться).

## Границы

Входит: граница ошибок, аварийный экран, ошибка `useLiveQuery`, сообщение об ошибке записи,
описание в `design.md`.

Не входит: проверка данных при чтении (шаг 3), транзакционная запись дня (шаг 2), изменения
`worker/`, сообщения о сбоях синхронизации напоминаний, новые классы и токены CSS.

## Критерии готовности

- Исключение при отрисовке экрана показывает аварийный экран с «Экспортом данных» и
  «Перезагрузить»; нижняя навигация работает, другие вкладки открываются.
- Ошибка запроса `useLiveQuery` показывает аварийный экран, а не пустой.
- «Экспорт данных» с аварийного экрана отдаёт тот же файл, что и «Экспорт» в «Настройках».
- Отказ записи показывает сообщение в листе; лист не закрывается; данные не меняются.
- На обычном пути разметка прежняя: существующие тесты, включая `ForecastInfo.test.ts` и
  `design-system.test.ts`, не изменены и зелёные.
- Аварийный экран проверен в светлой и тёмной теме, зоны нажатия ≥ 44 px.
- `npm test` и `npm run build` зелёные.
