# Шаг 2. Запись дня — точечным изменением в транзакции

Приоритет: высокий. Зависимости: нет. Видимых изменений нет.
Общие правила и порядок работы — `docs/refactoring-roadmap.md`.

## Проблема

Запись дня собирается целиком из снимка в памяти React и заменяет запись в базе. Для настроек
такая схема уже однажды теряла изменения, и её заменили транзакционным `updateSettings`
(`src/storage/repository.ts:83-92`: «чтобы быстрые переключения подряд не затирали друг друга»).
Для записей дня она осталась.

1. **Четыре места пишут запись дня целиком из снимка**:
   `saveDayEntry({ ...(entry ?? emptyDayEntry(date)), <поле> })` в `DaySheets.tsx:27`,
   `SymptomPicker.tsx:54`, `MoodPicker.tsx:28`, `NoteEditor.tsx:29`. Если запись есть, дата берётся
   из `entry.date`, а не из `date`.
2. **Снимок может относиться к другому дню.** `useLiveQuery` при смене зависимостей сохраняет
   прежнее значение, пока не придёт новое (`src/hooks/useLiveQuery.ts:9-17`). В
   `CalendarScreen.tsx:25` запрос зависит от `[day]`: после выбора другого дня есть минимум одна
   отрисовка, где `day` новый, а `entry` — от прежнего дня. `DaySheets.tsx:25` строит по нему
   диалог (выделение кнопок, «Отметить секс» / «Убрать отметку»), а запись в этот момент ушла бы
   на прежнюю дату. Вероятность мала (миллисекунды), но последствие — тихая запись не в тот день.
3. **Нормализация при запуске не атомарна.** `normalizeStoredPeriods`
   (`repository.ts:37-44`) читает, считает и пишет тремя отдельными операциями, параллельно со
   стартом интерфейса (`src/main.tsx:13`).

## Цель

Изменение записи дня — это «дата + изменённое поле», применяемое к актуальной записи в одной
транзакции. Значение из базы никогда не используется с чужими зависимостями.

## Набросок решения

1. `updateDayEntry(date, patch)` в `src/storage/repository.ts`: одна транзакция `rw` по `db.days` —
   прочитать и привести запись (`coerceDayEntry`), наложить изменение, привести снова, сохранить
   или удалить пустую (`isEmptyDayEntry`). Образец — `updateSettings`.
2. Четыре места из п. 1 «Проблемы» передают только своё поле: `{ sex }`, `{ symptoms, intensity }`,
   `{ moods }`, `{ note }`. Переключение отметки секса читает текущее значение внутри транзакции.
3. `useLiveQuery` не отдаёт значение прежних зависимостей: при их смене значение сбрасывается в
   `undefined` до первого результата нового запроса.
4. `normalizeStoredPeriods` выполняет чтение и запись в одной транзакции (`db.periods`, `db.kv`).
5. `saveDayEntry` остаётся, если нужен тестам или импорту.

## Проверить на этапе плана

- П. 3 убирает кратковременный показ записи прежнего дня под новой датой: вместо неё на те же
  миллисекунды сводка пуста. Убедиться, что это не даёт заметного мигания карточки дня; если даёт —
  выбрать вариант «значение помечено своими зависимостями» вместо сброса.
- Dexie: вложенные вызовы `getSettings` / `getPeriods` внутри транзакции должны использовать её же
  (таблицы перечислить в `db.transaction`).
- Как проверить п. 3 в окружении `node` без DOM: вынести правило «значение ↔ зависимости» в чистую
  функцию или обосновать иной способ.

## Границы

Входит: `updateDayEntry`, перевод четырёх мест записи, поведение `useLiveQuery` при смене
зависимостей, транзакция в `normalizeStoredPeriods`.

Не входит: запись месячных (`savePeriods` и `PeriodAction.apply` остаются — см. «Что решено не
менять» в плане), состояние push (шаг 5), сообщения об ошибках записи (шаг 1), схема хранения.

## Критерии готовности

- Тесты на fake-indexeddb (по образцу `src/storage/repository.test.ts`), написанные до кода:
  - два изменения разных полей одного дня, запущенные одновременно, сохраняются оба;
  - изменение дня X не меняет запись дня Y, даже если вызывающий держит устаревший снимок Y;
  - запись, ставшая пустой, удаляется; остальные поля сохраняются как были;
  - несуществующая запись создаётся из пустой с изменённым полем.
- В `src/ui` не осталось записи дня вида `{ ...entry, поле }`.
- После смены дня компонент не получает запись прежнего дня.
- Поведение листов «Самочувствие», «Настроение», «Заметки» и отметки секса прежнее; существующие
  тесты не изменены и зелёные.
- `npm test` и `npm run build` зелёные.
